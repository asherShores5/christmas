# Christmas Swap v1 spec

Date: 2026-11-08. Status: ready-for-agent. Terms are defined in `GLOSSARY.md`; the Cycle choice
is explained in `docs/adr/0001-three-year-cycle-with-swap-year.md`.

## Problem Statement

Every year my family has to work out who buys for whom across our four Households (Eliana, The
Shores, The Janz, The Wruks). Someone picks names, the result gets lost in a group chat, and by
next year nobody remembers who had whom, so the same pairs come up again while others never
happen. It isn't meant to be secret; we just need one fair list that everyone can check.

## Solution

A small public site at christmas.ashershores.com called "Christmas Swap". It shows this year's
Draw with some holiday flair: snow, the four Household cards shuffling, then settling into
Giver → Recipient rows with confetti. The Draw is computed in the browser from the year, so
everyone sees the same result without a server, and arrows let anyone look at past and future
years. Over every three-year Cycle each Household gives to each other Household exactly once,
and nobody has the same Recipient two years in a row.

## User Stories

1. As a family member, I want to open one link and see this year's Draw, so that I know who I'm buying for.
2. As a family member, I want the page to show the calendar year's Draw by default, so that I don't have to pick a year.
3. As a family member, I want the Draw to be the same on every device and every visit, so that nobody gets a different answer.
4. As a family member, I want to see every Pairing, not just my own, so that the whole family can check it.
5. As a family member, I want to never be my own Recipient, so that the swap makes sense.
6. As a family member, I want each Household to give exactly one gift and receive exactly one gift each year, so that it's fair.
7. As a family member, I want to give to each other Household once every three years, so that we rotate through everyone.
8. As a family member, I want never to have the same Recipient two years in a row, so that it doesn't feel repetitive.
9. As a family member, I want the no-repeat rule to hold across the boundary between Cycles too, so that the start of a new Cycle doesn't repeat last year.
10. As a family member, I want each Cycle's order to look random rather than a fixed pattern, so that it feels like a real draw.
11. As a family member, I want to press ← to see last year's Draw, so that I can remember who had whom.
12. As a family member, I want to press → to see future Draws, so that I can plan ahead.
13. As a family member, I want the ← arrow to stop at 2026, so that I'm not shown made-up history from before the site existed.
14. As a family member, I want the URL or page to make clear which year I'm looking at, so that I don't confuse years.
15. As a family member, I want to jump back to the current year easily after browsing, so that I don't get lost.
16. As a family member, I want gentle snowfall in the background, so that the page feels festive.
17. As a family member, I want the four Household cards to shuffle when the page loads, so that the reveal is fun.
18. As a family member, I want the cards to settle into Giver → Recipient rows automatically, so that I don't have to press anything.
19. As a family member, I want confetti when the Pairings appear, so that the reveal has a finish.
20. As a family member, I want a "Shuffle again" button that replays the animation with the same result, so that I can show it to someone else.
21. As a family member, I want sound to stay off until I tap a speaker icon, so that the page doesn't blast a jingle at me.
22. As a family member, I want to turn the sound off again, so that I'm in control.
23. As a family member who has reduced motion turned on, I want the plain list without snow, shuffle or confetti, so that the page is comfortable to use.
24. As a family member on a phone, I want the layout to fit a phone screen, so that I can check it anywhere.
25. As a family member, I want to read the Pairings with a screen reader, so that the result is accessible.
26. As a family member, I want to see the year's Notes (gift budget, exchange date, rules) under the Draw, so that I know the details.
27. As a family member, I want no Notes section shown when a year has none, so that the page stays clean.
28. As a family member, I want to add the site to my home screen, so that it opens like an app.
29. As a family member, I want the site to work offline after the first visit, so that I can check it without signal.
30. As a family member, I want the site not to show up in search results, so that our names aren't easy to find.
31. As Asher, I want the Households hardcoded in one config file, so that I control the list.
32. As Asher, I want to write each year's Notes in that same config file, so that updates are one edit.
33. As Asher, I want to swap a Household in the Household List from a given year, so that the swap can continue if the family changes.
34. As Asher, I want a Household List change to start a new Cycle that year, so that the rotation stays fair with the new list.
35. As Asher, I want past Draws to stay exactly as they were after a list change, so that history doesn't rewrite itself.
36. As Asher, I want the site to refuse a Household List that doesn't have exactly four Households, so that I can't break the schedule by accident.
37. As Asher, I want the Draw algorithm frozen and guarded by tests that pin known years, so that a later code change can't quietly change a Draw people already rely on.
38. As Asher, I want the same stack and deploy flow as App Connector, so that I don't have to learn anything new.
39. As Asher, I want prod deploys to wait for my approval, so that nothing ships without me.
40. As Asher, I want a $1/month budget alert on the app, so that a mistake can't cost real money.
41. As Asher, I want the site served at christmas.ashershores.com over HTTPS, so that it sits with my other apps.

## Implementation Decisions

- **Stack**: copy App Connector's setup: npm workspaces `web` (Vite + React + TypeScript PWA with
  a service worker) and `infra` (CDK). No Lambda, DynamoDB, Cognito or API.
- **Hosting**: S3 + CloudFront in us-west-1, certificate in us-east-1, Route 53 record
  christmas.ashershores.com in the existing ashershores.com zone, same personal account. Bucket
  refuses direct reads; CloudFront only. Single CSP source like App Connector; no off-origin
  requests at all. `noindex` via both a robots meta tag and a `robots.txt` disallow, plus an
  `X-Robots-Tag: noindex` response header.
- **Deploy**: GitHub Actions OIDC role that trusts only the `production` environment (Asher is the
  required reviewer); pushes to `prod` deploy. main and prod protected (PR plus test checks).
  Cost tag `app=christmas`, budget `christmas-monthly` $1.
- **Repo**: public `asherShores5/christmas`; local `my-stuff/personal/christmas`. Tickets in
  gitignored `.scratch/v1/issues/`.
- **Draw module** (the one deep module): a pure function from year to Draw, with no DOM, clock or
  randomness from outside. Rough interface:
  - `drawFor(year) → Draw | undefined` (undefined before the first Household List year, 2026).
  - A Draw lists four Pairings in a stable display order, plus whether it is a Loop or a Swap
    year and its Cycle number and position.
  - `currentYear(now)` returns the calendar year; the page passes `new Date()`.
- **Schedule**: each Household List version has a start year (first: 2026). From the start year,
  years are grouped into three-year Cycles. For each Cycle a seeded shuffle picks (1) an order
  of the four Households around a circle and (2) an order of the three offsets 1, 2, 3. In the
  Cycle's k-th year each Giver gives to the Household that many places ahead around the circle.
  Offsets 1 and 3 give Loops, offset 2 gives the Swap year, and each Giver meets each other
  Household once per Cycle with no repeat between consecutive years inside the Cycle.
- **Cycle boundary rule**: if the first Draw of a Cycle would give any Giver the same Recipient as
  the previous year (including the last year under an older Household List), the seed attempt is
  bumped (attempt 0, 1, 2, ...) until it doesn't. This is deterministic, so every browser agrees.
- **Randomness**: a small fixed PRNG written in the repo (not `Math.random`, not a library that
  could change) plus Fisher–Yates. Seed derived from (list start year, Cycle number, attempt).
  Once 2026 is live, the PRNG, seed derivation and schedule are frozen.
- **Household List config**: one typed config file holding the list versions (start year plus
  exactly four Households, each with a stable id and display label) and Notes keyed by year.
  Labels: Eliana, The Shores, The Janz, The Wruks. A list with anything other than four
  Households, duplicate ids, or out-of-order start years fails the tests and the build.
  Changing a Household's label doesn't change Draws (Draws use ids).
- **Page**: title "Christmas Swap <year>". Year shown comes from the URL (`?year=`) if present and
  valid, else the calendar year (flips Jan 1). ← is disabled at 2026; → has no limit. A "This
  year" control appears when browsing another year. Sequence on load and on year change: snow
  (continuous), card shuffle, settle into Giver → Recipient rows, confetti. "Shuffle again"
  replays the animation; the result never changes. Speaker toggle, muted by default; sound is a
  small bundled audio file played only after a tap. With `prefers-reduced-motion`, no snow,
  shuffle or confetti: the rows render immediately. Pairings are also real text in a list for
  screen readers. Notes render under the Draw only when the year has them.
- **Not linked anywhere**: no App Connector Tile and no portfolio card; Asher shares the link.

## Testing Decisions

- Good tests check behavior from the outside (what Draw a year produces), not how the shuffle is
  written. Asher chose to test the Draw module only, plus the CDK synth tests the stack already
  has; no page render tests or browser e2e in v1.
- **Draw module tests** (Vitest), over every year from 2026 to 2100:
  - Every Draw has four Pairings, every Household gives once and receives once, no Household is
    its own Recipient.
  - Every Draw is a Loop or a Swap year; each Cycle has exactly two Loops and one Swap year.
  - Within each full Cycle, each Giver gives to each other Household exactly once.
  - No Giver has the same Recipient in two consecutive years, including across Cycle boundaries
    and across a Household List change.
  - Same year gives the same Draw on repeated calls (determinism).
  - Years before 2026 give no Draw.
  - Pinned snapshot: the Draws for 2026–2031 are written into the test as literal values, so any
    change to the algorithm fails loudly.
  - Household List change: adding a second list version from a future year (test fixture) leaves
    every Draw before that year identical to before, and the new list starts a fresh Cycle.
  - Config validation: a list with three or five Households, duplicate ids, or unordered start
    years is rejected.
  - `currentYear` returns the calendar year (Dec 31 vs Jan 1 edge).
- **Infra tests**: CDK synth assertions as in App Connector (bucket blocks public access,
  CloudFront only origin, headers including CSP and X-Robots-Tag, deploy role trusts only the
  production environment, cost tag present).
- Prior art: App Connector's `web/src/tiles.test.ts` (config-file tests) and its `infra/test`.

## Out of Scope

- Wishlists, gift tracking, budgets beyond free-text Notes.
- Sign-in, passphrases or any secret mode (the Draw is intentionally public to the family).
- Individuals inside Households.
- Household Lists of any size other than four (adding or removing a Household needs code changes).
- Email, push or calendar reminders.
- Editing anything from the site; all changes are config edits plus a deploy.
- App Connector Tile and portfolio card.
- Page render tests and browser e2e (Asher's call for v1).

## Further Notes

- Why one Swap year every three: with four Households, "everyone every three years", "never
  mutual" and "never the same Recipient twice running" can't all hold. A Loops-only schedule was
  considered and rejected because it forces back-to-back repeats. See ADR 0001.
- The schedule math generalizes to other sizes (circle offsets), but v1 deliberately enforces
  exactly four.
- Because anyone can compute future years, there's nothing to hide; noindex just keeps family
  names out of search.
- First deploy needs Asher: `personal` AWS login, GitHub repo creation, `production`
  environment approval. Follow App Connector's `docs/first-deploy.md`.
